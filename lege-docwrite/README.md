# lege-docwrite

A page-native book writing environment. You write directly into a stable,
typeset paged book; underneath, the manuscript is a semantic structure
(book, part, chapter, section, block, run) with paragraph and character
styles, page masters and chapter templates, so it stays easy to reorganize
and export.

The basic nouns are **book, chapter, paragraph, page, source and style**.

## Principles

- Pages are derived; the semantic model is canonical.
- Typing latency is an architectural invariant: key → edit → reshape the
  affected paragraph → incremental repagination to convergence → damage →
  present. Everything else is asynchronous. Keypress-to-present is gated.
- `PageDown` is the next physical page; spread mode moves by spread; scroll
  gestures settle onto a page when they end.
- Research is first class: select a passage in a source PDF, keep a Source
  Note (document, page, passage, bibliography, annotation), cite it, and jump
  back to the exact page.
- Output: PDF generated by Lege, Markdown, IDML (not native `.indd`), EPUB
  perhaps later.

## Not goals

Real-time collaboration, track-changes workflows, mail merge, forms,
spreadsheets, free drawing tools, presentation features, macros, database
integration, Word compatibility.

## Layout

| Crate | What |
|---|---|
| `docwrite-model` | Book tree, blocks, runs, styles, masters, templates, edit transactions |
| `docwrite-typeset` | Shaping, line breaking, hyphenation, incremental pagination |
| `docwrite-export` | PDF, Markdown, later IDML |
| `docwrite-app` | Binary `lege-docwrite`: pixelkit host, page canvas, Book Map |

A nested Cargo workspace, excluded from the ecosystem root. From the
ecosystem root: `cargo docwrite`, `cargo docwrite-check`, `cargo docwrite-run`.
It path-depends on `lege-pdf/*` and on the sibling `../pixelkit` checkout.

Scope, decisions, milestones and cross-repo dependencies live in the AKR
ledger (`.akr/`); `docs/generated/` is rendered from it.
