Lege user guide

Lege turns scanned books and photographed pages into PDF or DjVu files suited to your reader. It separates pictures from text, cleans page backgrounds, adjusts margins, and compresses the result. Optional OCR adds search and can produce a text-only EPUB.

The desktop app and the lege command use the same processing core. Processing runs locally. The standard build includes the models; you do not need an account, a model download, or an external AI service.

Process your first book

  1. Add the source. Drop PDFs, image ZIPs, or folders of page images into the window, or use Add File and Add Folder. Each input becomes a book in the queue.
  2. Set the reading size. Enter the page height in pixels under Resolution. A fresh setup uses 1200. Use your reader's screen height as a starting point.
  3. Choose the treatment. For a typical scanned book, start with Preparation, Best text, layout detection on, and Original pictures. Use Preserve when the page's color matters.
  4. Try a few pages. Set a range such as 5-10. Include small text and an illustrated page. Turn on OCR if you need search; leave Flatten page off for ordinary flat scans.
  5. Choose the destination and process. Outputs go next to their inputs unless you choose an Output Directory, which then applies to the queue. Inspect the sample on the device you will read on before processing the whole book.

File tiles beside Process group inputs by kind and show counts. Page counts load in the background; you can keep adding files and changing options while they load. Process waits until the counts are ready. Queue shows the individual inputs; Cancel stops a running job.

Settings are remembered between launches. The defaults described here apply to a fresh desktop setup: PDF, JBIG2 encoding, Best text, layout on, Original pictures, OCR off, and Flatten page off.

Inputs and output formats

The main workflow accepts PDFs, folders of page images, and ZIP archives of page images, including Internet Archive JP2 ZIPs. Image collections support PNG, JPEG, JPEG 2000 (.jp2), TIFF, BMP, and PBM/PGM/PPM/PNM. DjVu is an output format, not an input format for this workflow.

Give page images consistent, numbered filenames and check the page count. Folder intake searches subfolders and selects the most common image extension as the page set, preferring JP2 in a tie. Other formats can be skipped to avoid including duplicate previews or thumbnails. Keep each book in its own folder and use one image format when every file should be included.

Lege writes a separate processed file. Keep the source: reducing resolution, binarizing, cropping, and lossy image encoding can discard detail that cannot be recovered from the result.

Preparation, Preserve, and text

Preparation

Preparation aims for readable pages on e-ink: clean text, a light background, and separately treated pictures. The Text row offers three choices. These control page appearance; the Encoding choices control how the resulting text is stored.

Text treatment in Preparation
ChoiceHow it worksTradeoff
BestThe embedded binarizer-tilenet neural model turns text into black ink on white paper. Large regions are processed in overlapping tiles.The default for scans, particularly tinted or yellowed paper. It can thicken fine text or lose pale marks on digitally generated pages.
FastAdaptive binarization combines Sauvola with background-normalized Otsu using GPU compute kernels.Useful for bulk conversion and as an alternative when Best changes fine strokes. It can retain more paper noise or show-through.
GrayscaleA crisp ink mask sits over a cleaned grayscale background, retaining gray edge detail and text antialiasing.Useful when strictly black-and-white text looks too harsh. Uses layered compression and can cost more space.

Best and Fast both use the adaptive CPU fallback if a hardware GPU is unavailable. Fast also falls back to the CPU if its GPU kernels fail. There is no adjustable fixed-threshold method in the current interface; the former threshold and Sauvola-k controls are retired.

Preserve

Preserve keeps page color using mixed raster content (MRC): a compressed color background plus a sharp ink layer. PDF uses JPEG 2000 and JBIG2; DjVu uses IW44 and JB2. Ink is currently rendered black. This is a way to retain more of a page's appearance while compressing it; the result is still resized and encoded, so it is not a lossless archive of the source.

Preserve replaces the Preparation text and picture treatments. The GUI turns off conflicting options such as dithering, Symbol mode, inversion, and reflow. Margins and resolution still deserve care if you want the original page composition.

Layout detection

Layout detection identifies text, pictures, tables, headings, captions, footnotes, and page furniture. It lets Lege protect picture regions from text binarization and supplies content bounds for cropping and reflow. It is on by default.

Lege 1.6 ships its own RF-DETR-S book layout model, v2. It was trained on 64,785 pages from 547 books, with labels corrected in bulk and 16,090 pages reviewed by hand. It replaces the older layout models. Its detected boxes are used without the old box-expansion and synthetic-region corrections. Contents lists, references, and formulas are treated as text rather than separate classes.

Pictures detected by the model stay picture regions, including drawings and maps; the old tone-based line-art filter is gone. Tables are text-like for binarization. Running headers, footers, and page numbers can be excluded from content crops and reflow, while footnotes are retained by normal cropping.

Detection can miss content or stop a box inside a picture, leaving a binarized rim. A header misread as a heading can survive cropping or enter reflow. Check illustrated pages and page edges in a sample.

With layout off, the page follows the whole-page text treatment and pictures lose their protected regions. This can suit pure line art, but Best may reduce photographs to sparse outlines. For problem pages, the CLI can skip layout selectively with --exclude-layout 1,3,7-10.

Flatten photographed pages

Flatten page straightens curved book pages and splits a photograph of an open spread into two output pages. It uses Lege-Dewarp ft4, the page-flattening model introduced November 14, 2026. Enable it beside Resolution, or pass --flatten on the command line.

The model estimates page shape and the gutter, refines each page, and samples the result from the original image before resizing to your target. Two embedded versions handle portrait and landscape views; these are the same model at different input shapes. A flat-page gate attempts to leave ordinary scans unchanged.

Leave it off for flat scans unless you have checked a sample. The gate is imperfect, especially on full-page photographs without text or clear page edges. It can warp an already flat picture. Thick page blocks and the left side of a spread can also give less accurate results. Flatten page is off by default.

  • Inputs: image folders, image ZIPs, and PDFs whose pages contain photographs or curved scans.
  • Hardware: a hardware GPU is required. If unavailable, Lege reports that flattening is skipped and processes the pages without it.
  • PDF limitation: pages are rendered as images and sent through the image pipeline. Existing PDF text layers and bookmarks do not carry over. Enable OCR to create new searchable text.
  • Other workflows: EPUB and raster reflow jobs ignore flattening. Splitting spreads changes the output page count.

Automatic single-page/spread detection is the default. For a uniform photo collection, --flatten-pages 1 forces one page per photo and --flatten-pages 2 forces spreads. Use --flatten-fast for one pass per page, trading some straightness for speed.

Pictures and covers

With layout enabled, choose how detected picture regions appear:

  • Original: retain continuous-tone color or grayscale pictures, separately encoded from the text. “Original” describes their treatment; the crops are still rendered, resized, and compressed.
  • Dithered: represent shades with black-and-white dot patterns. This can suit monochrome e-ink and reduce size, at the cost of tone and fine detail. JBIG2/DjVu use Stucki dithering; CCITT4 uses clustered dots.
  • JBIG2 halftone: an experimental PDF picture encoding that trades picture resolution for compact halftone patterns. It needs layout detection and JBIG2-capable output; it is unavailable in Compatibility mode and raster reflow.

Picture encoding is separate from PDF text encoding. Normal PDF picture regions use JPEG 2000; Compatibility uses JPEG pictures and CCITT Group 4 text. High quality raises picture and background quality in PDF and DjVu, usually increasing file size.

Separate cover treatment keeps source page 1 as a full-page picture. A range beginning after page 1 does not turn its first selected page into a cover; a range beginning at page 1 can retain cover treatment. Use --no-cover if the first page should be processed as an ordinary body page. --cover-format selects the cover/image encoding, with none disabling separate cover treatment.

Resolution, margins, and reflow

Resolution and page range

Resolution is in pixels, not DPI. Enter 1200 for proportional scaling to that height, or 1200x800 (height × width) for a specific canvas. 1200 800 is also accepted. Forcing both dimensions can alter page proportions. Higher values retain more detail and increase processing work and file size; enlarging a poor scan cannot restore missing detail.

Page ranges are one-based source page positions, not the printed page numbers: 5-10 selects the fifth through tenth source pages. Leave the GUI range empty for the whole book. A CLI range is positional, such as lege book.pdf 5-10.

Margins

  • Center margins: standardize and center the detected content within the page.
  • Crop margins: crop toward the content bounds and resize. Normal cropping retains footnotes and excludes detected page furniture.
  • Force crop: allow cropping past footnotes too. Use only after inspecting the result.

With layout disabled, pixel-based content bounds provide margin detection. Cropping can change page proportions; the current free-aspect crop uses the requested height and ignores an explicit target width. Marks close to the edge and incorrect detections can change the crop.

Raster reflow

Reflow rearranges the scanned words and lines into new pages for the target size. It can make small print readable without zooming. It requires layout detection and changes pagination and composition. Try prose first; tables, formulas, and complex page designs need inspection. Reflow is separate from OCR-based EPUB and does not require recognizing the text to rearrange its pixels.

Reflow replaces margin centering/cropping, cannot be combined with Preserve or inverted-input mode, and ignores Flatten page. PDF reflow uses raster CCITT4 pages rather than TrueTyping.

Inverted input

Use inverted colors for light text on a dark background. It inverts the input before processing and disables layout detection, so pictures no longer receive layout-based protection.

OCR and EPUB

OCR recognizes words for a search/copy layer. It is separate from visual text cleanup and from TrueTyping. Turning it on generates replacement recognized text. With OCR off, the normal PDF pipeline attempts to reuse extractable source text; it does not copy the original PDF layer unchanged. Flattened PDF input loses that source-text route.

  • Fast OCR: page recognition for a searchable overlay.
  • Thorough OCR: prepares and recognizes individual lines at higher detail. Use it for EPUB or when recognized text matters more than throughput. The CLI calls this mode best.

Windows uses the system WinRT OCR service; language availability depends on installed Windows OCR support. Standard Linux, macOS, and Android builds use embedded PP-OCRv6 small detection and recognition models through Lege's native GPU runtime. Tesseract is an optional Linux/macOS build backend, not a standard installation requirement.

In the desktop app, OCR also requests inferred metadata and an automatic table of contents from available text and layout headings. Existing PDF bookmarks take precedence when they can be carried into the output. On the CLI, request heading-based bookmarks with --auto-toc. Recognition, reading order, and heading detection can all be wrong; inspect copied text and navigation as well as the page image.

Add an EPUB

Select EPUB beside the PDF and DjVu format buttons to write a text-only EPUB alongside the chosen format. This turns on Thorough OCR. Direct CLI EPUB output is available with --text-format epub. The EPUB contains recognized paragraphs and chapter navigation, not facsimile pages or illustrations. Expect errors in difficult scans, tables, formulas, and unusual reading orders; review the text before relying on it.

PDF text encoding

Binarization chooses which pixels are ink. Encoding stores that result. Lossless compression of the resulting mask does not make the earlier cleanup, resizing, or cropping lossless.

  • JBIG2: the desktop default. Generic mode stores the black-and-white mask without symbol substitution.
  • Symbol mode: an optional JBIG2 mode that reuses matching glyph bitmaps for smaller files. It is lossy: a wrong match can replace one character with another. Leave it off when exact text appearance matters.
  • Compatibility: CCITT Group 4 text with JPEG pictures for readers that have trouble with JBIG2 or JPEG 2000. Available for binarized Preparation pages.
  • TrueTyping: traces printed glyphs into an embedded book-specific TrueType font. It can give smoother text at different zoom levels, but can change glyph shapes and may be slower or larger than JBIG2. It does not recognize words and does not replace OCR.

In the GUI, selecting TrueTyping enables Grayscale in Preparation. Returning to Best or Fast returns the text encoder to JBIG2. TrueTyping can also be explicitly selected in Preserve. Existing bilevel scan content may remain raster rather than being traced again.

DjVu uses its own JB2 text encoding; the PDF codec choices do not change it.

Models and hardware

Models included in the standard build
ModelRolePractical detail
RF-DETR-S v2Book layout detection.About 58 MB of weights. Keeps pictures separate and identifies content for margins, OCR, and reflow.
binarizer-tilenetBest black-and-white text treatment.About 1.65 MB of weights. A small tileable network distilled from the earlier Sauvola model and document-binarization data.

Fast binarization is an algorithm, not another neural model. The old whole-image Sauvola neural model is no longer embedded by default; it remains an optional legacy build/runtime override. Custom builds may also omit layout, OCR, or dewarp features.

Lege runs model inference through its native wgpu compute runtime. Desktop GPU processing uses Vulkan on Windows and Linux and Metal on macOS; Direct3D 12 is no longer used on Windows. The standard build does not need ONNX Runtime, DirectML, or CUDA installed separately. Model and shader initialization can take time at the start of a job before page progress begins.

Without a usable hardware GPU, layout detection can be disabled for the run, Best/Fast use adaptive CPU binarization, and flattening is skipped. These fallbacks change the available processing: unprotected pictures can be binarized with the page. Check the reported status and output rather than assuming the requested model ran. Update your GPU driver if Vulkan or Metal initialization fails.

Command-line examples

Run lege without arguments for the guided prompts, or pass a PDF, folder, or ZIP directly. Quote paths containing spaces. lege --help lists processing flags; lege --help debug lists inspection/export tools.

The simple CLI and desktop defaults differ. lege book.pdf uses CCITT4 text, Original pictures, layout on, and a 1200-pixel target height. The desktop defaults to JBIG2. Name the format explicitly in repeatable commands. Supply a page range as a positional argument, such as 5-10.

Prepare a scanned book, then try a faster sample

lege book.pdf --text-format jbig2 --target-height 1200
lege book.pdf 5-10 --text-format jbig2 --binarization fast

Flatten a folder of book photographs

lege "book photos" --flatten --text-format jbig2 --ocr
lege photos.zip --flatten-pages 2 --flatten-fast --text-format jbig2

Keep page color, or retain grayscale text edges

lege book.pdf --preserve --text-format jbig2 --high-quality
lege book.pdf --grayscale --text-format jbig2

Make DjVu, searchable PDF, or text-only EPUB

lege book.pdf --text-format djvu --ocr
lege book.pdf --text-format jbig2 --ocr-mode best --auto-toc
lege book.pdf 1-20 --text-format epub

Fit a reader or choose a destination

lege book.pdf --text-format jbig2 --crop-margins --target-height 1600
lege book.pdf --text-format jbig2 --target-height 1200 --target-width 800
lege book.pdf --text-format jbig2 --output "processed books"
lege first.pdf second.pdf --text-format jbig2

Prefer explicit --target-height and --target-width flags in scripts. In the positional syntax, a lone number below 500 is interpreted as a page number. Use --text-format djvu to choose DjVu. For a picture-only PDF that skips binarization, use --text-format jpeg --image-only.

Checking results and solving problems

  • Fine text becomes heavy or pale marks disappear: compare Best with Fast or Grayscale at the same resolution. Best is tuned for scans and can be less suitable for a digitally generated PDF.
  • Pictures become black blobs or outlines: check that layout actually ran and Images is set to Original. Without layout, text binarization can affect the entire page.
  • A dark rim appears around a picture: the detected picture box may end inside its boundary. Changing binarization can change the rim; the current model's boxes are not expanded automatically.
  • A flat illustration becomes bent: turn Flatten page off. Its flat-page gate can misclassify full-page photographs.
  • Headers remain or footnotes disappear: compare with margins and reflow off, then check crop settings. Force crop permits removing footnotes; layout errors can also affect content bounds.
  • The result is larger: check resolution, High quality, Grayscale/Preserve, and TrueTyping. Already compressed sources may not shrink. More detected pictures can also increase size while retaining content previously binarized.
  • Search or copying is wrong: compare OCR modes and confirm language support. A clean-looking page does not establish OCR accuracy, and TrueTyping alone does not supply recognized words.
  • The reader cannot display the PDF: try binarized Preparation with Compatibility enabled. Test on the actual device before converting the full book.
  • A folder has fewer pages than expected: check filenames and image extensions. Mixed-format folder intake can select only the dominant format.

The GUI's Log keeps the most recent 30 processing entries; inspect the run log when a job fails or reports a GPU fallback. Debug exposes additional diagnostics. Clear Log removes processing history from the app. For layout inspection from the CLI, use lege book.pdf 5-10 --layout-visualize 1200 to export pages with detected boxes and labels.
